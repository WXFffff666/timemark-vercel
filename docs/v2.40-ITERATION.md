# v2.40 全链路优化战役（R17–R19 三轮递增）

日期：2026-10-31 · 基线：0d88234（v2.39 收官）· 规则：先做后打分，每轮分数必须高于上一轮才进下一轮。

## 一、探索结论（直扫，非代理）

- **OCR 5 端点零 UI**（GET / 状态、GET /results、POST 上传抽取，2MB 上限、类型白名单、无引擎 503 ocr_disabled）——v2.38 遗留最大缺口。
- **备份 import 端点无 UI**：backup.ts 有 /export、/export-encrypted、/import 三个端点；DataSources 页只做了 remote-backup 与导出，restore（导入恢复）无入口。
- **92 处原生 confirm()/alert()**：移动端体验差（无法样式化、字体小、暗色不适配）。
- **31 处空 catch**：静默失败，用户无反馈。
- **CommandPalette 方向键不循环**：`Math.min(index+1, …)` 到底即停（:216-219）。
- 暗色模式遗漏仅 3 处（良好）；EmptyState 已覆盖 26 页但部分无 CTA。
- doses/calendar-sync/parcels 已有 UI（早前记录过时，已核实）。

## 二、调研结论（新产品借鉴）

- 2026 个人管理应用趋势：**AI/OCR 自动捕获**（SmartScan 式拍照→结构化）、**文本智能识别日期**（Apple Reminders 在输入文本时自动识别日期/时间/位置）、**auto-snooze**（[Lindy 2026 提醒应用评测](https://www.lindy.ai/blog/best-reminder-app)、[Bill.com 票据扫描](https://www.bill.com/blog/best-receipt-scanning-app)）。
- 空状态设计规范（NN/g）：**视觉 + 一句话说明 + 显式 CTA**，空屏是引导时刻而非留白（[NN/g](https://www.nngroup.com/articles/empty-state-interface-design)、[UX Planet](https://uxplanet.org/empty-state-design-a-practical-guide-94ad0adbda45)）。
- 吸纳：OCR 页做成「拍照/上传 → 抽取 → 一键存文档」的自动捕获闭环；EmptyState 加 CTA；删除类操作统一确认弹窗。

## 三、三轮计划

### R17（第一轮：补最大缺口 + 卫生）
1. **OCR 页**（/ocr，挂 Documents 组）：引擎状态卡（503 时说明如何启用）→ 上传/拍照（capture=input file）→ 抽取结果（文本 + 结构化字段）→ 存为文档/复制；GET /results 历史列表。i18n + nav + 路由 + 搜索索引文档。
2. **CommandPalette 方向键循环**：到底回环到首、到顶回环到尾。
3. **空 catch 修复（首批 10 处）**：用户可感知的失败路径改为 setError/toast 文案；纯忽略的（隐私模式 localStorage）保留但加注释。
4. 打分维度：功能完整 / bug 密度 / UI-UX / 移动端 / 健壮性。

### R18（第二轮：移动端交互统一）
1. **ConfirmDialog 组件**（基于 Dialog）：danger 变体 + 需输入确认文本的可选模式；替换高频删除类原生 confirm() ≥ 20 处（跨 ≥ 8 页）；alert() 换 toast/行内错误。
2. **EmptyState 加 CTA**：可选 action prop；补 Analytics/AnnualReport/ApiPortal 等无 EmptyState 页面的关键空态。
3. EventForm 快捷日期 chips（今天/明天/下周一/月底——调研的智能日期轻量版）。
4. 打分（必须 > R17）。

### R19（第三轮：收敛 + 全链路自查）
1. **备份 restore UI**（DataSources 页）：选择导出文件 → 显示导入预览摘要 → 文本确认（输入 RESTORE）→ 执行 + 结果报告；危险操作双重门。
2. 自查：tsc 0 错 / 前后端测试全绿 / build 全绿 / 关键页面真浏览器冒烟 / 残留 confirm() 计数对比。
3. 终审打分（必须 > R18）；账本收官 + 记忆更新 + 提交推送部署。
