# v2.42 全链路优化战役（R23–R25 三轮递增）

日期：2026-10-31 · 基线：v2.41 收官 9.6 · 规则：先做后打分，每轮分数必须高于上一轮。

## 一、探索结论

- **undo 快照体系存在但只接了决策卡**（audit.service：snapshot + 一次性 claim + TTL 窗口；Security 页有审计卡）——通用删除流（事件/联系人/文档）未接快照。
- i18n zh/en 50/50 对称无缺口；PWA 完善（offline.html/network-first/push/snooze）；后端无 N+1 环；Dashboard 请求并行无瀑布。
- `<img>` 仅 4 处且全带 alt；全站 0 处 `loading="lazy"`（影响小，头像场景顺手加）。
- habit_logs 有 logged_on 全量历史——热力图数据就绪。
- v2.41 素材遗留：Swagger UI（决定不做——引 ~1MB 依赖对 6 端点性价比低，如实记录）、OCR 多文件批量、toast action。

## 二、调研结论

- GitHub 式贡献热力图是 2026 习惯一致性的主导视觉隐喻，连击为核心留存机制（[Modelo](https://www.reddit.com/r/ProductivityApps/)、365-Day Notion 模板等均采用）；周回顾层（进度条/周/月/年视图）叠加在打卡之上是 planner 应用标配趋势（Griply/Discy 主打 review ritual）。
- 吸纳：习惯热力图（52 周网格 + 连击头部）+ 周回顾页（确定性数据驱动，不假 AI）。

## 三、三轮计划

### R23（第一轮：可撤销删除体系）
1. **toast 支持 action 按钮**：`toast.success(text, { action: { label, onClick }, durationMs })`——单按钮，右侧文字按钮；单测。
2. **三个高频删除流接内容级撤销**：事件（Dashboard handleDelete / EventForm 删除入口如有）、习惯（Habits 页删除）、模板（Templates 删除）——删除成功后 toast 带「撤销」，点击重新 POST 原数据（诚实语义：内容恢复，id/createdAt 为新值，toast 文案注明「已恢复（新记录）」）。
3. 打分。

### R24（第二轮：周回顾页）
1. **/review 周回顾页**：本周范围（周一至今）聚合——事件完成/新增计数（stats/daily）、提醒成功率、习惯连击榜、7 天内到期前瞻、活跃目标进度；顶部数据驱动建议（确定性规则：如「本周提醒失败 3 次→建议查看触发日志」「3 个习惯连击 ≥7→保持节奏」）。全部来自现有端点，零后端改动（不够就诚实缩减）。
2. nav 数据组入口 + i18n + 路由；空态引导。
3. 打分（必须 > R23）。

### R25（第三轮：热力图 + OCR 批量 + 收敛）
1. **习惯热力图**：Habits 页选中习惯渲染 GitHub 式 26 周网格（过去半年，7 行×26 列，色阶 0-4），头部连击/最长连击/完成率；数据 habit_logs 现有端点。
2. **OCR 批量**：文件 input multiple → 队列逐个识别（进度 x/y）→ 结果列表逐条存文档/合并文本复制。
3. 收敛自查：前后端测试 / tsc / build / 真浏览器冒烟（撤销流/周回顾/热力图/批量）。
4. 终审打分（必须 > R24）；账本收官 + 记忆 + 推送部署。
