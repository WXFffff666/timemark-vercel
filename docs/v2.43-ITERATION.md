# v2.43 全链路优化战役（R26–R28 三轮递增）

日期：2026-10-31 · 基线：v2.42 收官 9.9 · 规则：先做后打分，每轮分数必须高于上一轮。

## 一、探索结论（本战役最大收获：a11y e2e 揪出两个线上真 bug）

- **a11y 套件 4 失败 → 全部有因**：
  1. **PageHeader 移动端标题被挤没（产品 bug）**：390px 下右侧 shrink-0 宽按钮组（ProfileSwitcher/添加/更多）把左组压到宽度 0——h1 w=0 实证（toBeVisible hidden 的真相是零宽，不是遮罩/动画）。**影响所有带宽按钮组页面的移动端标题显示**。
  2. **DataManagement policy 无空值防御**：mock/API 突变下 `data.policy[key]` 直接白掉整个 Settings 页（ErrorBoundary 挡住但页面不可用）。
  修复后 a11y 6/6 全绿；新增 e2e/page-header.spec.ts 回归探针（390px 标题宽 >60px 断言）。
- 安全面干净：dangerouslySetInnerHTML 仅 2 处且走 sanitizeHtmlPreview（前后端都过）；_blank 全带 rel。
- i18n 50/50 对称；Dashboard 请求并行无瀑布；后端无 N+1。
- v2.42 素材遗留：undo 推广（联系人/文档/到期项）、热力图 52 周年视图、周回顾导出/邮件订阅。

## 二、调研结论

- 移动端 header 布局：宽按钮组 + 单行 header 是常见反模式，主流做法是**标题区 flex-1 保底 + 操作组允许换行**（Material 3 app bar 规范）——本次修复与之一致。
- 年视图热力图（52 周）是 GitHub 式追踪器的标配进阶（365-Day Notion 模板等）——高价值低成本（组件参数化 weeks 数）。
- 周回顾导出：Markdown 下载是最小可用形态（用户已有 .md 导出先例：LocalAI 对话导出），邮件订阅复用 digest 通道成本高——本轮做 Markdown 导出。
