# v2.44 加载全链路优化 + 依赖升级战役（R29–R31 三轮递增）

日期：2026-10-31 · 基线：v2.43 收官 9.9 · 探索：加载链路专项代理（47 次实测）+ 依赖盘点 + 联网调研。

## 一、探索结论（实测数据）

**首屏链（P0 级）**：
- 首屏 JS ~1.42MB：entry 465.9KB + **vendor-charts 418.7KB** + vendor-react 247.1KB + vendor-motion 128.9KB + CSS 156KB，全部 modulepreload，挂载前零可见内容。
- **vendor-charts 进首屏的根因**：manualChunks 对象式分组把 `clsx` 归进 charts 组（normalized.includes 匹配），而全站基础工具 `cn()` 依赖 clsx → 同步组件（toast/button）把它拉进 entry 图。真用图表的只有 4 个 lazy 页（Analytics/AnnualReport/Medications/AgentConsole）。
- **checkAuth 阻塞所有受保护页首帧**：isLoading 门控全屏 spinner；失败后串行 `/auth/refresh` + 二次 `/auth/session`（最多 3 串行往返）；超时 12s。
- **MeshBackground**：SVG feGaussianBlur stdDeviation=80 对两个 ~40vw 椭圆全屏模糊，低端手机首帧 paint 开销大，每页常驻。
- **/contacts 后端 SQL 无 LIMIT 全表拉取**（全站唯一漏网；events 都有 cap 200）。
- **AnimatePresence mode="wait"**：切页固定 +180-360ms。
- **vercel.json 无 Cache-Control**：hash 资产未配 immutable，315MB 模型权重靠浏览器默认策略。
- **部署后旧 HTML 引用已删 chunk** → ChunkLoadError 白屏（无重载策略）。
- Today 页 /events 重复拉两次；Dashboard 挂载即预取 9 个路由 chunk 抢带宽。

**依赖现状（整体很新，仅少数偏旧）**：React 19.3 / vite 8.3 / zod 4.6 / hono 4.13 / tailwind 4.3 / recharts 3.10 全新。偏旧：lucide-react 0.344（→1.65，v1.0 breaking：brand icons 移除——已核实未用 brand 图标）、@radix-ui/react-dialog 1.0.5→1.1.23、/slot→1.2.4、date-fns 3.3→5.x、tailwind-merge 2.2→3.x。

**重复模式**：fmtTime/fmtBytes/fmtSize 5 处重复；toLocaleString('zh-CN') 散布 9 文件。

**调研采纳**：hash 资产 immutable（Vercel 官方规范）；路由级分割减首屏 40-70%；stale chunk 刷新一次兜底；lucide v1 迁移清单。

## 二、三轮计划

- **R29 首屏瘦身**：manualChunks 重划（vendor-ui 组解放 charts）/ MeshBackground CSS 化 / vercel.json Cache-Control / ChunkLoadError 兜底。
- **R30 加载体验**：checkAuth 乐观渲染（有本地凭证即首帧渲染）/ AnimatePresence 去 wait / Today /events 去重 / contacts LIMIT / 预取 idle 化 / AI 轮询延后。
- **R31 依赖升级 + 收敛**：radix/date-fns/tailwind-merge 批量升级 / lucide 1.x 迁移 / lib/format.ts 统一 / 全量收敛自查。

## 四、打分记录

### R29（第一轮）执行记录
- **首屏 preload 链 810KB → 401.5KB（-50%）**：真凶与探索代理假设不同——实测 dist 反查，clsx 本就不在 charts chunk；真因是 **rolldown 对所有 manualChunks 命名 chunk 一律写进 index.html 的 modulepreload**（新增 vendor-ui 立即出现 preload 实证）。修法：**charts 组不再命名**（continue 跳过）→ 变普通按需 chunk，只被 4 个图表 lazy 页拉取。探索代理的 clsx/use-sync-external-store 假设均被实验证伪——「命名 chunk 全 preload」才是事实。
- **MeshBackground 去 SVG filter**：feGaussianBlur(80) 改纯 CSS 双 radial-gradient（视觉近似零 filter 开销）。
- **vercel.json Cache-Control**：/assets/* 与 /models/* immutable 1y、/search-index.json 1d、/ must-revalidate。
- **lazyPage 兜底**：45 个 lazy 页全部换 lazyPage——ChunkLoadError 自动整页刷新一次（sessionStorage 防循环），部署后旧 HTML 不再白屏。
- 验证：tsc 0 / 前端 360 / build 全绿；真浏览器图表页（Analytics recharts 渲染/Medications）按需加载正常。

### R30（第二轮）执行记录
- **checkAuth 乐观渲染**（auth.store.ts）：本地有 accessToken/保持登录标记时 isAuthenticated 初始 true + isLoading false——首帧不再等 /auth/session（冷启动常态 >5s）；真 401/403 走既有踢回+清 token；/login 重定向仅在校验完成后执行（防乐观态抖动）；HttpOnly cookie 无凭证场景保持原路径。
- **AnimatePresence 去 mode="wait"**：exit 元素脱离布局流（absolute），切页立即挂新页，消除固定 180-360ms。
- **Today /events 去重**：OverdueTodosCard 改用共享 event store（in-flight 去重），Today 首屏同一请求不再发两遍。
- **/contacts LIMIT 500**：全仓库唯一无上限列表查询收口；profile 过滤走独立 if 分支（两段纯字面量 SQL——Mimosa SQL 门禁连续拦截模板插值 5 次的绕行经验：候选 diff 中新增的 `${...}` 一律判注入，纯字面量 + if 分支可通过）。
- **Dashboard 预取 idle 化** + **AI 状态轮询延后**（requestIdleCallback + 10.5s 兜底）——首屏数据请求不再被预取/探测抢带宽。
- 验证：前端 360 / 后端 1760 / 双端 tsc 0 / build 全绿；真浏览器乐观首帧（chunk 后即内容）、快速连续切页无叠影无报错。
